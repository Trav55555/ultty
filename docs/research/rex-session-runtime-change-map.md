# Session runtime change map

Source review at `c718910fad12749ec53379ab09256ae5a52a826b`, 2026-11-12. This is an implementation plan, not a change to runtime behavior. It covers persistent live VT and native TUI sessions across UI detach, then optional attach through an explicitly selected SSH connection. It does not claim processes survive a runtime crash, machine restart, or explicit session destruction. Network listeners, embedded Tailscale, arbitrary remote access, multi-user service, plugin frameworks, and durable process checkpointing are out of scope.

## Decision and principal blocker

Propose a single authoritative, headless session runtime per user session. It owns PTYs, parser/grid state, tabs and pane identities, native-app sockets, native scenes, app event delivery and lifecycle. A window becomes an attachable viewer/controller. First implement an in-process runtime seam with the existing window behavior unchanged; then place that same runtime in a separate process and attach over an owner-only Unix socket. Only after local behavior is proven, carry the same bounded attach protocol through an explicitly started SSH subprocess using stdio. No TCP listener is necessary.

This is a proposed architecture. The current code does **not** already have that process boundary. A PTY-only daemon would strand native apps and stop lifecycle work when the window disappears. It would also leave rendering and input code borrowing local manager/session objects. These are the changes that must accompany extraction.

## Verified current ownership and flow

1. [`App`](../../crates/ultty/src/app/mod.rs#L128) owns `TerminalManager`, `ProtocolServer`, `ControlServer`, the renderer, window, clipboard and accessibility adapter. Startup creates a window and GPU renderer, derives initial grid dimensions from renderer metrics, then starts the native socket server before launching shells. Per-tab `ULTTY_SOCKET` is installed in the child environment. PTY readers wake winit; there is no independent runtime pump. See [`App::new`](../../crates/ultty/src/app/mod.rs#L264) and [`tab_env`](../../crates/ultty/src/app/mod.rs#L1558).
2. [`TerminalManager`](../../crates/ultty/src/terminal_manager.rs#L260) owns `ManagedTerminal` objects, tabs, focus, split trees and geometry. Each `ManagedTerminal` owns an [`EventLoop`](../../crates/ultty/src/event_loop.rs#L304), which owns the PTY child and reader thread. The reader parses VT and answers terminal queries; the UI drains terminal events in `process_all`. The parser itself lives on the reader thread, including partially received escape/UTF-8 state. Dropping `EventLoop` stops and joins the reader; dropping [`Child`](../../crates/ultty/src/pty/child.rs#L251) terminates then kills/reaps an unexited child. Window process exit thus cannot be repurposed as detach without moving ownership.
3. [`App::update`](../../crates/ultty/src/app/update.rs#L192) polls the native server, ticks animations and keepalives, handles clipboard requests, binds native sessions to panes, synchronizes viewport sizes, pumps in-band frames, polls control requests, processes terminal events and pairs inline surfaces. Some are runtime duties even with no viewer; redraw, notification, clipboard, input and a11y are viewer duties. Moving only `TerminalManager` stops the rest of this loop when the window closes.
4. [`ProtocolServer`](../../crates/ultty/src/protocol/server.rs#L67) owns per-tab Unix listeners, app links, in-band state and anchor pairings. [`NativeSession`](../../crates/ultty/src/protocol/session.rs#L102) combines transport, scene, Taffy layout, atomic frame queue, region subscriptions/focus, scroll and animations, inline surfaces, clipboard requests and handshake/keepalive state. The native app connection must stay attached to the runtime, not to a UI that can disappear. [`pump_in_band`](../../crates/ultty/src/app/update.rs#L54) links parsed APC bytes and replies to that server; currently it allows in-band only for a single-pane tab and ends the session on split or foreground-process-group change. Preserve those rules unless changed by a separate design.
5. [`bind_native_sessions`](../../crates/ultty/src/app/native_panes.rs#L15) maps a socket peer's process group to a pane, and viewport synchronization uses current pane grid dimensions. Inline surface pairing combines VT anchor events and scene surfaces and can rasterize into VT rows. Both must continue without a window and preserve ordering. The authoritative runtime needs a last-known geometry; a headless default and resizing policy must be explicit.
6. The existing [`SessionData`](../../crates/ultty/src/session.rs#L10) v1 persists titles, directories, focus and a split tree with pane positions; [`from_session`](../../crates/ultty/src/terminal_manager.rs#L1269) allocates new numeric IDs and spawns new shells. It is workspace reconstruction, not a live-process or terminal-state checkpoint. `ultty -e` is deliberately excluded from saving the last session. [`App` save path](../../crates/ultty/src/app/mod.rs#L1615).

## Extraction boundary and files

The first deliverable can remain in the existing `ultty` crate to avoid prematurely turning every internal type into a public cross-crate API. Proposed `crates/ultty/src/runtime/` would own the orchestration below, with an independently driveable poller, wakeup and timers. A later `ultty-runtime` crate is possible only after auditing the complete transitive closure; moving files into a new crate does not itself remove the binary's graphics dependencies.

| Current owner | Proposed owner and changes |
| --- | --- |
| `terminal_manager.rs`, `event_loop.rs`, `pty/`, `pane_layout.rs` | Runtime owns children and tab/pane model. Separate model commands from direct access through `TerminalGuard`; runtime loop continues draining reader events and applying close-on-exit policies. Preserve PTY query replies, foreground-group checks, resize and shutdown. |
| `protocol/server.rs`, `protocol/session/`, `scene/`, VT/native inline pairing in `app/update.rs` | Move server polling, keepalives, `pump_in_band`, binding, pairing, app-link replies and scene mutations into runtime. Keep negotiated capabilities and existing app protocol intact. Audit `platform/socket.rs`, `inherit_dir.rs`, config/limits and `ultty-protocol` dependencies. Runtime must work with zero window or renderer. |
| `app/native_panes.rs`, pixel geometry, `app/input.rs`, `app/render.rs` | Client converts window/font metrics to a proposed cell viewport and sends input tagged with pane and attachment. Runtime applies authoritative resize/focus policy. Client renders received views; replace direct borrows from manager/server with client projection APIs. Handle partial output and reconnect explicitly. |
| `app/update.rs`, `app/wakeup.rs`, `app/control*` | Split headless event pump from view-only window work. Decide per control command whether it targets session runtime or an individual UI window. Screenshot, physical window resize and window actions require a viewer and must return a clear unavailable result while detached; do not pretend headless execution succeeded. |
| `app/accessibility.rs`, `a11y/`, clipboard, notifications and IME | Keep OS adapter, focus, input method, physical clipboard and attention on the UI side. Forward bounded semantic changes or derive a11y trees from synchronized state. Runtime keeps subscription/semantic state needed by live native apps, but must not issue host UI operations itself. |
| `platform/runtime_files.rs`, `platform/socket.rs`, control paths, `ulttyctl` | Introduce runtime-owned stable endpoint discovery and owner-UID authentication. Audit PID-based filenames and stale cleanup: viewer exit must not unlink a live runtime endpoint. Preserve `ULTTY_SOCKET`, `ULTTY_PANE`, control-token behavior and process group isolation for child apps. |

### Producer backpressure and launch receipts

The current native transport [`send_message` and `flush_writes`](../../crates/ultty/src/protocol/session/transport.rs#L117) append encoded replies to `write_buf` and transfer in-band replies to `outgoing` without a cap in those paths. Do not assume the existing native producer link is bounded just because the proposed viewer queue is bounded. Define independent limits for each app socket and in-band output, including a clear overflow/disconnect policy that does not silently lose protocol replies, control frames or final surface events. Exercise an app that stops reading while its output and resize events continue, both attached and detached. Audit other layers before claiming an end-to-end bound.

[`Child::spawn`](../../crates/ultty/src/pty/child.rs#L61) returns `Ok` in the parent after fork. The child tolerates `chdir` failure and exits 127 if `execve` fails. A runtime creation receipt can currently mean PTY allocated and child forked, not successful execution or correct working directory. If the product requires an exec-confirmed receipt, design a close-on-exec error pipe and an explicit setup/error contract, with fork-safe child operations and tests for missing executable and invalid directory. Preserve or deliberately version the existing tolerated-directory behavior. Process readiness is a separate application-specific claim, even after exec succeeds.

### Font, layout and geometry

[`LayoutEngine`](../../crates/ultty/src/scene/layout.rs#L65) builds Taffy nodes from `SceneTree` and computes in cell units. [`scene/text_layout.rs`](../../crates/ultty/src/scene/text_layout.rs#L1) uses Unicode column width for shared wrap/raster behavior; this path is not itself a `cosmic-text` font-system dependency. The GUI renderer uses scaled font metrics to choose cell dimensions, and pane pixel geometry feeds grid sizing. Thus headless layout need not import wgpu merely to compute the scene, but needs explicit cell counts and pixel metrics for terminal queries, image placement and pane geometry. Verify the extracted dependency graph and tests rather than assuming the entire `scene` module is GPU-free. Different client fonts/sizes must not independently resize a shared PTY without an arbitration rule.

Proposed phase-one policy: exactly one controlling attachment sets pane dimensions and native layout, with a defined headless last-known size. Other viewers, if later allowed, do not resize or send input until control is transferred. Prefer one viewer initially to make the contract testable. Client-local scroll, selection, GPU caches, animation clock and pixel geometry stay per attachment unless an existing protocol behavior requires authoritative scroll. Native app layout and replies must correspond to the chosen authority, not two competing viewers.

### Clipboard, accessibility and native app constraints

Native clipboard reads are currently restricted by active-tab and connection rules; in-band sessions cannot read the clipboard. OSC 52 writes are governed by behavior config and focused pane in [`App::update`](../../crates/ultty/src/app/update.rs#L350). Preserve those checks across the boundary, avoid replaying old clipboard actions on reattach, and deny or promptly answer unavailable reads while detached rather than leaving a producer blocked. Do not transmit OS clipboard content to remote clients by default. Native event subscriptions, focus and live-region changes must remain sufficient for a reattached UI's [`a11y` snapshot](../../crates/ultty/src/app/accessibility.rs#L30); a11y platform adapters and window ownership remain local. Define what happens to a live announcement produced without an active accessibility subscriber instead of claiming historical announcements are replayed.

## Proposed attach protocol and snapshot

Do not overload the existing native app protocol: it is the app-to-terminal scene contract, not a trusted viewer-to-runtime replication protocol. Add a separately versioned, bounded `runtime_wire` module, likely in `ultty-protocol`, and keep its framing and auth independent of `control.rs`. Example shapes, to be refined before implementation:

```rust
struct RuntimeEpoch([u8; 16]); // fresh per runtime incarnation
struct SessionId([u8; 16]);
struct PaneId([u8; 16]);
struct Revision(u64);
struct AttachRequest { session: SessionId, protocol: VersionRange, role: AttachRole }
struct AttachSnapshot { epoch: RuntimeEpoch, revision: Revision, session: SessionView }
enum RuntimeEvent { PaneChanged { pane: PaneId, revision: Revision, change: PaneChange }, /* ... */ }
```

Authenticate a local peer before exposing output or input, and use strict byte, nesting and collection limits. In a single runtime serialization point register the observer, capture a consistent committed snapshot and revision, then deliver subsequent ordered changes. Client applies snapshot first and events after its revision. Bounded outgoing queues must disconnect slow clients and force a fresh attach rather than silently omit events. A changed runtime epoch invalidates stale handles and queued operations; requests report target-not-found or stale epoch, not accidental reuse. Define ordering between input, resize, snapshot, PTY output, native `EndFrame`, child exit and disconnect; no partial native frame may leak as a committed scene. Use structured errors and negotiated protocol versions. These are design requirements, not existing guarantees.

A snapshot must cover the material needed to reconstruct what the UI shows and how it interacts:

- Session/tab/pane identities, ordered split tree/ratios, active and focused pane, title/status, dimensions, lifecycle and revision.
- VT primary and alternate screens, scrollback, cursor and saved cursor attributes, modes, palette, links, image contents/references, shell metadata and inline anchor state. Viewport selection and transient local interaction can remain client-local if represented separately. Current [`Terminal`](../../crates/ultty-vt/src/grid/terminal.rs#L234) contains much more than visible cells; it is not a ready-made snapshot codec. Bound image/history sizes and negotiate chunking.
- Native scene tree with region IDs, constraints, styles, content, semantics, surface roots and placement/pairing, computed layout or deterministic recomputation inputs, focus and display-relevant scroll state. The authoritative side keeps app subscriptions, pending frames, stream/transport state, peer credentials and responses; a viewer should not receive authority to impersonate the app. Preserve live scene while producer is connected, even if no viewer exists.
- If clients consume serialized state changes, the parser remains solely authoritative in runtime. If instead clients replay raw PTY bytes, a complete parser checkpoint including partial sequences and charset state plus a race-free byte offset is needed; screen cells alone cannot reproduce future parsing. Existing [`AnsiParser`](../../crates/ultty-vt/src/ansi/mod.rs#L639) has partial CSI/OSC/APC and UTF-8 state. The output tee, query responses, flow control and synchronized cut would require separate design and tests. Start with authoritative snapshots and revisions; do not assert full-fidelity incremental deltas already exist.

Avoid serializing mutexes, file descriptors, `Instant`, renderer caches or raw internal Rust layout. Define semantic versioned DTOs and rebuild derived caches. A UI attach snapshot is not a crash-recovery format: a runtime crash loses live processes. Disk history or best-effort workspace restoration is a later, separately specified feature.

## Identity and v1 migration

Current `TabId` and `TerminalId` are process-local `usize` counters, used in pane layout, environment, socket names and control messages. `SessionData` v1 uses tab indices and pane positions. Allocate new stable opaque runtime/session/pane IDs for live handles, scoped by runtime epoch; never treat the existing v1 array index as a persistent identity. Either maintain a runtime-local mapping for current `ulttyctl`/environment numeric IDs or version those contracts explicitly, and preserve current behavior for existing apps and scripts during migration.

Do not rewrite old saved files during attach. Implement a version-aware importer that validates v1 layout, assigns fresh IDs, starts fresh shells as today, and records the new format only on an explicit successful save using atomic replacement. Invalid or unknown future versions fail safely without truncating the original. Keep `-e` save exclusion. State whether migration creates a new live session versus attaches to an existing one; it cannot resurrect the old processes. Add golden fixtures for v1, malformed layout, unknown version, crash during save, and new-format round trip. Audit control IDs and runtime socket names before deciding whether external consumers need a compatibility adapter.

## SSH attach proposal

Only after local attach passes: launch a user-selected `ssh` child to run a fixed remote runtime attach command, carrying the framed protocol over its stdin/stdout. SSH's normal user configuration and authentication apply; local runtime remains local-only by default. Keep remote stderr separate from framed stdout, and handle missing executable, auth prompts, remote version mismatch, interruption and child cleanup. Avoid constructing remote shell commands from unsanitized user data. Do not reuse APC in-band app framing as this protocol or assume a remote server is installed. Existing ulttui native in-band over SSH remains supported independently.

Disconnected SSH means the viewer is detached; it says nothing about whether the remote runtime is still running. The remote runtime must have an explicit independently supervised lifetime. Reconnection reauthenticates through SSH and performs a fresh snapshot/epoch handshake. There is no automatic installation, Tailscale enrollment, external listener or guarantee of reattachment after remote restart in this phase.

## Ordered implementation gates

1. **Runtime seam, unchanged process model.** Extract a `SessionRuntime` owner with `poll(now)`, commands and events; move native polling/in-band/anchor pairing and child cleanup under it. Inject a headless wake mechanism and size rather than winit. Gate: existing workspace tests, clippy and GUI smokes pass; a headless integration test drives an actual PTY plus socket and in-band native app without winit or GPU, including keepalive, resize, surface pairing and foreground checks. Demonstrate no change to `ultty -e`, control, clipboard or a11y behavior. Roll back the seam if parity fails.
2. **Local detached lifetime.** Add explicit runtime process, owner-only attach endpoint and lifecycle commands. Ensure UI disconnect does not drop runtime-owned children; explicit destroy does. Gate: launch real shell and native app, detach the only window, observe continued output and working native link, reattach and interact; verify resize, focus, OSC query, surface and cleanup. Kill runtime and verify clients report loss, do not claim survival. Check endpoint permissions, stale cleanup and existing control compatibility. Retain the current single-process path as rollback until acceptance.
3. **Snapshot and flow control.** Introduce versioned snapshot/ordered updates and bounded queues, covering VT and native state above. Gate: compare real snapshots before/after reattach under concurrent output and frame boundaries; test split escape sequences, alternate screen, scrollback, images, style, hyperlinks, native focus/semantics and inline anchors; a slow client disconnects and resynchronizes without corrupting the authoritative session. Verify no duplicate input or clipboard replay and version rejection. Fuzz decoders and size limits. Measure bytes, CPU, allocation and latency against the current in-process path; reject representation if overhead is unacceptable.
4. **SSH transport, opt in.** Gate against a real SSH server with separate processes: auth failure, remote binary/version failure, disconnect/reconnect, remote runtime exit, resized terminal, concurrent output and native app semantics. Verify no listener on startup and no spontaneous remote actions. Compare direct and relay routes only where separately authorized and report conditions. Roll back by disabling the optional transport while retaining local behavior.

The ordering may interleave a minimal local attach codec with phase 2; phase 2 is not accepted until its actual live VT and native state is visible after reattach. This sequencing prevents a VT-only daemon from being called complete. No benchmarks or tests were run during this source review.

## Open decisions

Choose one authoritative viewer and explicit detach-versus-close UX, idle-runtime and explicit shutdown behavior, durability/cleanup policy, and whether native animation uses runtime or per-viewer clocks. Resolve whether a headless clipboard request is denied or delivered to a later focused viewer; never queue a stale privileged action silently. Define limits and exact semantic snapshot delta types after inventorying every `Terminal`, `Buffer`, `NativeSession`, image and scene field. Measure the dependency closure and decide whether a separate crate saves shipped dependencies before extracting it. Multiple simultaneous controllers, persistence across daemon restart, generic remoting, external network access and Tailscale embedding require separate design and acceptance gates.
