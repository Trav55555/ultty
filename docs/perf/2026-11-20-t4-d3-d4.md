# T4 check after the Vulkan and startup changes

Ultty met the X11 startup target at 83 ms to a titled window. Alacritty took
212 ms. On Wayland, Ultty took 420 ms and Alacritty took 244 ms. Ultty's
resident set size (RSS) after the feed remained above Alacritty's on both
displays. Compared with the [November 19 run](2026-11-19-t4-rerun.md), Ultty's
X11 startup median fell from 349 ms and its RSS fell from 174 MiB.

## Environment

- AWS g4dn.xlarge, Tesla T4, NVIDIA 580.178.04. Ultty release build
  `7edcdf17043082d2bbf6009083ebd1f1a89576b2`, after PRs #179 and #181.
- Alacritty 0.16.1. X11 used headless Xorg with openbox on the T4. Wayland
  used headless sway 1.11 with `WLR_RENDERER=gles2` at 60 Hz.
- Both sessions used 120×40 cells, DejaVu Sans Mono 11, three interleaved
  rounds, and 200 keypress samples per launch and latency case.

The first X11 attempt omitted the installed Alacritty binary from `PATH`.
We reused the instance, builds, corpus settings, and sample counts.
X11 and Wayland finished collecting samples before the Markdown reporter hit
a division by zero on Alacritty's idle CPU median. The tables use the saved
JSONL samples.

## Comparison

| Display | Measure | Ultty | Alacritty |
| --- | --- | ---: | ---: |
| X11 | Exec to titled window | 83.09 ms | 212.26 ms |
| X11 | RSS after feed | 136.47 MiB | 114.78 MiB |
| Wayland | Exec to titled window | 420.38 ms | 244.25 ms |
| Wayland | RSS after feed | 184.77 MiB | 157.82 MiB |

Alacritty's X11 startup ranged from 186 to 1,676 ms across the three
launches. Ultty ranged from 82 to 84 ms. Each Ultty launch finished sooner
than the fastest Alacritty launch in this run.

Two extra X11 launches sampled process mappings after the first GPU frame.
With Vulkan narrowing enabled, Ultty loaded the NVIDIA driver and had zero
`libLLVM` mappings. With narrowing disabled, the process still rendered on
the T4 and had four `libLLVM` mappings. RSS at that point was 106.4 MiB with
narrowing and 153.0 MiB with all drivers available.

## CPU-first prototype

We enabled `ULTTY_CPU_FIRST_FRAMES=1` for two additional X11 rounds with 100
keypress samples per launch and case. Both rounds used the same release
binary as the three baseline rounds.

| Measure | Disabled | Enabled |
| --- | ---: | ---: |
| Keypress to pixel, idle | 3.83 ms | 3.81 ms |
| Keypress to pixel, 10 MiB/s flood | 5.70 ms | 5.52 ms |
| Keypress to pixel, maximum flood | 22.41 ms | 22.32 ms |
| ASCII throughput | 132.26 MiB/s | 129.94 MiB/s |
| RSS after feed | 136.47 MiB | 136.57 MiB |

The enabled ASCII median was about 1.8% lower and below the disabled
launch-median range of 131.55 to 134.05 MiB/s. The shorter enabled run ran
after the disabled rounds. A matched, interleaved comparison is still
needed for the steady-state acceptance check. The new CPU chrome and
continuous Wayland handover also still need hardware checks.

## Commands

Run from the checked-out Ultty source on the T4. The paths below match the
bench instance's build layout.

```bash
export PATH="$HOME/.cargo/bin:$HOME/ubench/alacritty/bin:$PATH"
out=$(mktemp -d)
args=(--terminals ultty,alacritty --rounds 3 --k2p-samples 200
      --ultty-dir "$HOME/ubench/target/release"
      --bench-dir "$HOME/ubench/target/release")
DISPLAY=:0 scripts/bench/compare.sh --session x11 --out "$out/x11" "${args[@]}"
WLR_RENDERER=gles2 scripts/bench/compare.sh --session wayland --out "$out/wayland" "${args[@]}"
DISPLAY=:0 ULTTY_CPU_FIRST_FRAMES=1 scripts/bench/compare.sh --session x11 \
  --out "$out/x11-cpuff" --terminals ultty --rounds 2 --k2p-samples 100 \
  --ultty-dir "$HOME/ubench/target/release" --bench-dir "$HOME/ubench/target/release"
```
