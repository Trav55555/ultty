# T4 three-way comparison on `main` after page storage (2026-11-11)

The 2026-11-08 run compared Ultty, Ghostty and Alacritty on the T4 before
ADR 0022's page storage, and its Wayland latency probe did not work. This
is the same campaign on current `main` (#108 merged), with the fixed
Wayland probe, so all three terminals now have Wayland latency numbers.

## Environment

- AWS g4dn.xlarge (Tesla T4, NVIDIA 580.178.04, 4 vCPUs), us-east-1, on
  demand, launched from the bench image `ami-0fe200d7ed965618f` (Ubuntu
  26.04.1, kernel 7.0.0-1016-aws, Ghostty 1.4.0 built from source,
  Alacritty 0.16.1, sway 1.11). The image's setup step found everything
  installed; only Ultty was built.
- Ultty `f66d10df6b62` (`origin/main`, #108 merged), release build on the
  instance (rustc from `rust-toolchain.toml`).
- Ghostty 1.4.0, Alacritty 0.16.1.
- X11: headless Xorg on the GPU (virtual 2560x1440 screen) with openbox.
  Wayland: private headless sway 1.11, `WLR_RENDERER=gles2`, 60 Hz output.
- 120x40 cells (checked with `stty size`), DejaVu Sans Mono 11, padding 0,
  10,000 lines of scrollback, cursor blink off. Claim class `live-realgpu`.

## Commands

The steps of `scripts/bench-aws.sh --role gpu`, run on the instance under
`nohup` so a dropped SSH session could not stop them, without the headless
VT step that `aws-remote.sh run gpu` adds (it was not needed and would not
have fit the instance's two-hour safety stop):

```bash
UBENCH_TERMINALS=ultty,ghostty,alacritty ubench/aws-remote.sh setup gpu
ubench/aws-remote.sh build ubench/ultty-f66d10d.bundle f66d10df6b629cffa590d062d6a775f549950757
# then, from the checkout, after starting Xorg as aws-remote.sh's session_x11 does:
ARGS=(--terminals ultty,ghostty,alacritty --rounds 3 --k2p-samples 200
      --ultty-dir ~/ubench/target/release --bench-dir ~/ubench/target/release)
DISPLAY=:0 scripts/bench/compare.sh --session x11 --out .../x11 "${ARGS[@]}"
WLR_RENDERER=gles2 scripts/bench/compare.sh --session wayland --out .../wayland "${ARGS[@]}"
```

Defaults otherwise: corpora ascii, sgr-dense, unicode-mixed and
cursor-redraw at 16 MiB, fed three times per launch; latency idle, under
10 MiB/s and under maximum output; 60 s idle; 1, 8 and 32 tabs. Three
rounds, terminal order shuffled per round, 200 key presses per launch and
case (600 per row). Both sessions finished with no failed measurement.

## Interpretation

- On the T4, Ultty now out-throughputs Ghostty on all four corpora (level
  to 8% on ascii, 18–64% on the rest) and has 6–7 times lower idle
  keypress latency, about a quarter of Ghostty's memory at 32 tabs, and
  starts 230–330 ms sooner.
- Alacritty keeps three leads: sgr-dense and unicode-mixed throughput
  (20–27% and 32–38% ahead), latency under output on X11 (12.4 against 22.4
  ms at maximum flood), and startup (180–200 ms sooner; OpenGL against
  the NVIDIA Vulkan device and swapchain, see 2026-11-08). On Wayland its
  latency lead under output disappears into sway's frame pacing.
- The maximum-flood X11 latency remains the largest gap to the best
  terminal, as on 11-08: page storage made the VT core faster but did not
  change how soon a key is drawn while the PTY thread is saturated.

These are one instance's numbers (`live-realgpu`, n=9 throughput, n=600
latency). They support the comparison above; they are not release
baselines by the README's rules.

## Caveats

- **Cold first launch.** Round 0's startup samples are 18.5 s (Ultty), 13.0
  s (Ghostty) and 2.7 s (Alacritty) on X11: the first exec of each binary
  after boot reads blocks of a volume restored from the image's snapshot,
  which EBS loads lazily. The median of three hides it; the warm launches
  are 371–400 / 608–630 / 196–197 ms on X11 and 423–428 / 760–762 / 240–250
  ms on Wayland. Alacritty's round-0 RSS is also higher (174 and 219 MiB
  against 114 and 158), and Ultty has one slow ascii sample in each session
  (69.7 and 79.0 MiB/s against 132–140); medians and IQRs are robust to
  these.
- RSS, startup and idle rows have three samples and the tab rows one, so
  `analyze.py` gives them no verdict.
- Alacritty's "tabs" are windows in one process and are not equivalent.
- The Wayland output composites on demand at 60 Hz, so Wayland latency is
  counted in compositor frames (resolution one frame), not against a
  display clock; X11 times are to pixels in Xorg's framebuffer, not
  photons.
- The 4-vCPU instance ran only the harness (1-minute load 0.2–3.0 during
  the runs).
- Raw results (2.5 MB `results.jsonl` per session, plus logs, corpora and
  binaries) were copied back to the workstation and are not committed. The
  instance is gone.
